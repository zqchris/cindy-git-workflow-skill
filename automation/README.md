# 可选 PR 自动跟进与旧版迁移

当前唯一工作流入口是根目录 [SKILL.md](../SKILL.md)。普通开发不默认安装后台任务。本目录只说明已授权自动跟进的边界，**不提供可直接安装的 watcher 或调度模板**；不要将本文当作宿主已支持某项能力的证明。

## 原任务直接接收事件

用户已明确授权持续跟进，且宿主确有可用实现时，采用单向链路：

```text
GitHub 当前 PR 的新证据 → 确定性检查/去重 → 原开发会话
```

不经过 PR 总管，不新建裁决、watcher 或替身会话，不让多个 session 交换进度。收到通知后，原任务仍先核对用户目标、停止范围和真实远端状态；通知不能授权改码、启动设备或合并。

部署前需要验证的契约：

- 精确绑定仓库、PR、原 owner 和任务；一条有效跟进，重复安装不能重复投递。owner 失效时报告原任务绑定问题，不另找会话接管。
- 无新增可行动证据时不唤醒模型。去重依据实际 head/事件和处置状态；“投递成功”不等于“意见已处理”，不能因此吞掉未完成工作。
- 通知只含原文证据、链接和必要范围，不附加新产品决策或扩权指令，不自动催他人。失败保留证据，有限重试，持续失败停止重试并报告原因。
- 用户叫停跟进后暂停投递，普通新事件不能恢复。用户仅叫停测试环境时，仍可处理允许的 PR 事件，但绝不能恢复启动。
- 安装后回读归属、去重和实际投递结果；没有验证就不能说“自动跟进已生效”。任务终态后在授权范围内停用本 PR 的专属跟进，保留用户工作区和停止记录。

本公开包未实现上述自动化契约。若宿主缺少能力，正常交付代码/PR 并如实说明没有后台跟进；不要读取宿主私有数据库、复制另一台机器的配置或为补能力另建常驻服务。

## 从旧版迁移

旧公开包 v4.7/v4.8 的 `automation/git-workflow/`、`automation/agent-ops/`、PR 总管 prompt、heartbeat 登记和规模/轮数硬闸已从当前安装包移除。它们保留在 Git 历史供调查，**不能作为当前恢复或安装清单**。根 skill 的版本号现为 2.0.0，与旧 automation 的独立编号不是同一序列。

更新这个仓库不会自动停止使用者已经安装的调度，也不会删除旧安装目录中的残留文件。迁移时：

1. 只读列出本机旧版安装副本、指向它们的软链和明确关联的调度，核对用户的暂停意图与当前任务归属。
2. 展示要替换/停用的具体对象，按用户对迁移的授权执行；未授权的在用任务不动，不批量覆盖全局 skills。
3. 停用已确认的旧总管及其自动拉起入口，回读确认；备份私有状态供恢复，不提交、不跨机复制。移出旧的可加载 skill 副本，避免新旧规则同时生效。
4. 安装根目录单一 `cindy-git-workflow`，合并用户自己的必要偏好；不继承发布者的私人授权。若存在新 watcher，必须另按上面的实际契约检查，不能假定升级已部署。

迁移结束分别报告：文件版本、旧自动化是否退出、新跟进是否验证。单纯 pull、复制文件或读到这篇文档都不代表运行环境完成迁移。
