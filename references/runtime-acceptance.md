# 真实运行验收

使用当前任务代码，证明用户目标确实可用。遵守 SKILL.md 的启停、任务归属和授权边界；验收要求不能恢复已被用户叫停的启动权限。

## 怎样才算测过

1. 选定成功路径、受影响的失败/恢复路径、必须保持的已有能力。先确定结果，再选择测试方式，不按截图数、分钟数或测试数量完成任务。
2. 核对 worktree、提交、未提交变更、运行版本、进程/端口和隔离数据目录。新代码必须实际加载；旧安装包或另一 worktree 的热更不能证明当前实现。仅提交相同已测内容时可关联证据，改变行为后重验受影响部分。
3. 通过真实 UI、CLI 或服务入口操作，等到最终结果。修改后读回，涉及持久化时再次启动测试实例确认；跨端/异步流程追到真实执行端及用户看到的终态。mock、构建通过、HTTP 200、页面打开都不能单独替代完整场景。
4. 记录步骤、预期、实见、版本/环境和证据位置。UI 留视觉证据，后台留事件/状态读回。未运行、失败、通过分别写；公开材料去除账号、token 和私有日志。

## 按变化选场景

| 变化 | 核心通过条件 |
| --- | --- |
| UI、交互、产品文案或样式 | 在实际页面完成受影响动作，确认显示和提交结果；检查本次涉及的加载、空态、错误态或主题，不只看首页。 |
| 数据库升级、持久化格式 | 用受支持旧版本的代表性非空测试数据，经真实升级入口启动；核对值、数量、关联和关键读写；再次启动确认不丢数据、不重复迁移。覆盖首次安装，并按设计验证中断/重试或备份恢复，不编造未承诺的降级能力。 |
| 执行位置迁移，如从客户端转到服务器 | 从既有测试配置迁移，通过用户入口确认目标服务实际执行，结果回到原会话，配置/历史/权限按约定保留，原端不重复消费；按产品承诺验证客户端断连以及服务重连/重启后的恢复。字段变化或“迁移成功”提示不够。 |
| 跨端、远程或异步状态 | 串起输入、传输、执行和结果展示；验证相关取消、切换、重连或恢复，确认终态与持久状态一致，不串旧结果、不重复执行。 |
| 后端、脚本、CLI | 真实入口配隔离数据，核对输出、副作用及受影响失败路径；有客户端消费者时补端到端确认。 |
| 纯非运行文档 | 检查内容、引用、示例与实现是否相符，不启动产品。若改可执行脚本，实际运行相关脚本场景。 |

数据库只用测试夹具或已授权的安全副本；不在唯一正式数据上尝试迁移。测试对外消息、真实服务和生产操作需已有明确授权，不能因“验收必须”扩大权限。

## 准备环境，而不是反复让用户登录

优先复用用户指定工具、已有隔离登录态和设备，核对实际占用后使用。不为每轮验收新建空 profile，不搬运正式凭证。端口被占用时查归属，选择本任务隔离资源；不自行找另一 session 协调，也不改它的服务。

启动、依赖、路由、缓存和预览问题，先解决权限内可修部分。预览入口坏不等于账号未登录。用户远程操作时给其实际可用的入口，不能只让用户去本机窗口。确需登录或验证码时一次说明入口、最小操作和恢复条件；没有回调就说明回复后续做，不虚构自动恢复。

等待仅覆盖依赖该输入的步骤。继续独立的代码、自审、回归及已授权 PR 处置；不新建替身任务，不重复报同一阻断。必要隔离 Desktop 重启沿工程授权执行，但用户叫停后持续禁止，不能借修环境重新启动。

## 验收缺项约束哪一步

| 状态 | 可以继续 | 不能宣称或执行 |
| --- | --- | --- |
| 首次 PR 的核心行为未测 | 准备环境、实现、自审、定向验证 | 不宣称已验收；无针对该项的明确豁免，不提交正式待审 PR |
| 核心已测，指定设备/环境补充验收待办 | 按原约定送审，推进独立修复 | 原约定阻断的合并/发布/结案仍不能完成 |
| 已有 PR 的独立修复已验证 | 按授权推送、回复/Resolve 已解决的问题 | 不把另一项缺口写成已解决，不声称整体 Ready |
| 本轮修复本身尚缺关键验证 | 继续可做验证，保留准确状态 | 不用无关测试冒充通过 |
| 用户叫停测试环境 | 自审及不触发被停环境的相关检查 | 不因通知、冲突或验收门禁重启；不循环请求豁免 |

用户指定的先验收后推送顺序、真实远端门禁仍有效。一般“快点”“提交”不等于豁免；不把核心路径改名为补充路径。明确豁免只调整指定项，不写成测试通过。

## 证据复用与交付记录

后续 review/冲突修复先回答：哪条已测路径变了？旧证据为何失效？需要实际运行回答什么问题？只有成立时补相应场景，并先检查停止范围。无关改动不重开整套环境，相关改动也不能借“小修”逃避验证。

在已有 PR 的验证部分记录即可，不另建审批系统。例如：

```text
版本/环境：<commit + 本任务隔离实例>
操作：<入口、输入及恢复步骤>
预期/实见：<可观察结果>
证据：<脱敏截图或读回记录>
缺项：<具体场景、原因、影响的交付阶段、下一步>
沿用证据：<原版本及本轮未影响该路径的依据，如有>
```
